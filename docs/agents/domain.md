# Domain docs

This repository uses a single domain context.

## Read before exploration or design

- CONTEXT.md: the project glossary.
- Relevant decisions under docs/adr/.

If these do not exist, proceed. Domain-modeling creates them
when terminology or decisions are actually resolved.

## Writing rules

Use the glossary's terms in specs, tickets, tests and explanations.
Keep CONTEXT.md a glossary; implementation plans belong elsewhere.
Record consequential decisions and alternatives in docs/adr/.
Surface conflicts with existing ADRs rather than silently overriding them.
